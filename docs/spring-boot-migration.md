# Перенос TripAnalyzer с Spring Boot 2.3 и Java 11

1. Зафиксировать JSON обоих примеров, сортировку по времени, границу breakThreshold и HTTP Basic в тестах. Подменить внешний геокодер.
2. Перенести единственную конфигурацию Security на SecurityFilterChain и UserDetailsService. Сохранить admin и имя переменной BASICAUTHKEY, исключить логирование и резервное значение секрета.
3. Перейти на Java 21 и Spring Boot 4.1.x. Для этого небольшого сервиса проверить конечную сборку напрямую. При несовместимости локализовать проблему через 2.7.x и 3.5.x.
4. Создавать результат отдельно для каждой поездки. Дать Spring управлять одним Google Maps клиентом и его завершением. Оставить прежние правила расхода, остановок и округления.
5. Обновить образы сборки и запуска. Выполнить Maven verify и проверить HTTP-запросы локально. При наличии Docker проверить также запуск образа.
6. Оставить результат в локальной ветке. Облачный пайплайн сам публикует изменения, поэтому его запуск в эту проверку не входит.

## Локальная проверка

Для сборки выбрать JDK 21 и выполнить `./mvnw clean verify`. Тесты запускают HTTP-сервер на свободном порту и используют тестовый геокодер. Для запуска с Google Maps задать переменные окружения `APIKEY` и `BASICAUTHKEY`, затем выполнить `java -jar target/trip.jar`. API принимает `POST /v1/trip` на порту 8080 с HTTP Basic и пользователем `admin`.

Ожидаемые значения расхода для example1.json и example2.json — 3,7 и 7,4 л/100 км. Во втором примере три заправки и четыре остановки, одна из которых также входит в список заправок. В тестовых ответах города обозначены округлённой широтой координат.
